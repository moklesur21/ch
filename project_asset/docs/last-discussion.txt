  How data gets to the live site (short version)

  You never copy the database. The seeder is deterministic — same anchor + RNG seed 20260722 ⇒ identical numbers everywhere — so the same demo-tools plugin regenerates the dataset on the live box via its token-protected REST API.
  Full ordered checklist is in live-migration.md; in brief:

  1. One-time deploy (SFTP/SSH): pro plugin build → pdwchs-demo-tools plugin (the catalog travels inside it) → northline theme → wp-config constants (PDWCHS_DEMO_ALLOW, PDWCHS_DEMO_TOKEN from openssl rand -hex 24, lockdown constants)
  → Freemius production license → setup-storefront → one-time wipe-legacy.
  2. Then and forever: ./scripts/live-refresh.sh — POSTs the refresh, polls until done (auto-resumes one stall), verifies, and confirms "LIVE OK — same numbers as local". Run it the morning of any prospect demo.

  Bonus finding while testing: the live REST path currently returns a WordPress 404 (not the WAF 403 the runbook feared) — automated requests reach WordPress, so the deploy may not need a WAF exception at all.
